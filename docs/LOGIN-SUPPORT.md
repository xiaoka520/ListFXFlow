# Mac 登录页与锁屏页共享输入

范围：Mac 系统启动后的登录窗口与锁屏。Windows 登录前共享已按要求移除，Windows 必须已登录并运行桌面应用。Windows 应用从 build 43 起以管理员权限运行；UAC 安全桌面期间暂停输入并保留连接，返回普通桌面后自动恢复，仍不能直接控制 UAC 弹窗。不包括 FileVault 开机解锁前；此时 macOS 和第三方应用尚未运行。

先在正常桌面完成一次双端连接，确认雷雳网卡、Mac IP 和屏幕排列正确。Mac 登录组件只接受当时已经配对的设备。换机、重置配对、修改屏幕排列后，重新执行组件更新。优先使用上次成功连接的本机网桥地址，地址不存在时使用实际可用地址，持续检查地址变化和监听失败并自动重试；不把失效 IP 强行写入系统接口。

## 启用

1. 两端先更新当前构建。Mac 主应用通过 DMG 安装；普通应用更新不等于受保护的 Mac 系统组件已经更新。
2. Mac 打开主界面的“权限设置”，在“登录前共享”区域点击“安装组件…”（已安装时显示“更新组件…”），在系统安装器中由本人完成管理员授权。组件会复制到受系统保护的位置，并注册 LoginWindow 代理及正常登录后的启动代理。
3. Windows 保持登录并运行普通应用。若安装过 build 18 系统服务，新安装器或新应用首次启动会申请管理员授权清理旧组件，没有新的 Windows 服务或登录页输入功能。
4. Mac 组件安装后，先测试 Mac 锁屏，再测试退出登录或重启后的 Mac 登录页。Mac 辅助功能和输入监控授权仍需有效；组件不更改系统隐私权限。

Windows 锁屏时释放输入并停止共享，解锁后自动恢复。Mac 在登录完成后由正常用户应用接管，连接可能短暂重建。

Mac build 21 参考 ThunderDisplay 的独立 LoginWindow 代理：先核对 root 和 LoginWindow 图形上下文，持续等待网桥与有效显示器；显示器初始化不执行桌面的“停止共享”流程。登录前使用带 Mach-O 标记的 Quartz 会话输入，仍检查系统事件发送和输入监控权限。登录后释放旧输入和监听端口，再请求已配置用户的桌面启动任务。

Mac“权限设置 → 登录前共享”里的“运行状态”显示最近一次实际运行的阶段、时间和退出前原因。也可运行应用内的 `Contents/MacOS/ListFXFlow --login-status` 读取。状态文件 `LoginSupport/login-state.json` 只含运行元数据，root 所有、普通用户可读；不包含按键、密码或配对密钥，跨重启的历史记录只用于诊断。

登录界面只提供键鼠，不启动文件或文字剪贴板。Mac 锁屏暂停剪贴板，解锁后恢复。程序不读取、缓存或记录输入的密码，诊断仅包含状态、异常类型和计数。

## 配置与移除

- Mac 系统组件位于 `/Library/Application Support/ListFXFlow/LoginSupport`。配对配置和日志在 root 独占的 `Private` 目录；配置不会进入分发的 DMG、ZIP 或 PKG。
- 旧 Windows 系统组件的 `ListFXFlowLogin` 服务及 `Program Files/ListFXFlow Login Support` 目录由迁移清理逻辑移除；不保留机器身份、监督进程或输入工作进程。
- Mac 从“权限设置 → 登录前共享”选择“移除组件…”，完成系统安装器授权。也可运行组件目录中的 `uninstall.sh`，需要管理员权限。
- Windows 不再提供登录前共享按钮。迁移清理只在检测到旧组件时运行。安装器从 build 43 起也需要管理员授权，以便更新并退出同等权限运行的应用。

## 验证边界

当前自动检查覆盖加密连接、固定设备身份、登录配置校验、保存地址的优先顺序、地址消失/恢复和监听重试，以及构建打包。它们不能证明 macOS LoginWindow、TCC 或 Secure Input 行为已通过；真实 Mac 锁屏和登录测试尚未完成。Windows 旧服务迁移清理也仍需在目标机器执行验证。

设计依据：[Apple 对 LoginWindow 代理上下文的说明](https://developer.apple.com/forums/thread/696859)。
